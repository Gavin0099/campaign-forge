# L03：先證明值得操作與重玩

狀態：**研究／實作規格完成；Gameplay 實作未授權、未執行。**

研究基線：`00146ba5d0da44734af38e855022b3383a80471b`；2026-10-22（台北）。本輪分支 `codex/playable-l03-research`。使用者要求先研究、不得安裝新引擎或直接擴寫玩法；本輪不修改另一個 AI 的 worktree、不合併 main、不改正式故事或 S3／S4。B 美術保留為候選，不代表人工美術通過。

建議先沿用 React 18＋SVG，把「玩家決策 → 敵人回應 → 目標進度 → 勝敗 → 重試」做成一個有期限的小型灰盒。玩法的單一問題是：**在敵人施壓時，玩家是否願意為了接船或護送車隊，改變站位與攻擊順序，並想再試另一種做法？** 更換引擎不會替我們回答這個問題。

## 必須先修正的可達性

`walkable(open)` 移除橋中央 `(4,4)`、`(5,4)`，三名我方起點全在左岸，絞盤 `(8,1)` 在右岸。讀取現有純模組、忽略單位占格與每回合步數的最寬鬆洪泛搜尋，三人仍都到不了絞盤或相鄰格。開閘左岸連通區只有 36 格；封閘的連通區有 83 格。

這是**地形連通性實測**，不是可玩戰鬥測試。完整數值與方法見 [connectivity-evidence.json](connectivity-evidence.json)。直接加「守絞盤」勝利條件會產生無解開局。提案保留 11×9 與橋分支，改 Demo 部署到右岸；新起點需追加授權，不能偷偷當成既有故事安排。

## 技術路線與最小 PoC（均未執行）

「重用」是模組層級判斷，不冒稱可量化的程式百分比；實作成本是估計，未經 spike 證明。

| 路線 | 可重用／必須補寫 | 版本、維護與反對理由 | 最小隔離 PoC／去留條件 |
| --- | --- | --- | --- |
| **A React＋SVG，先做** | 保留 React、劇情選單、素材、BFS 概念、格線互動；新增純領域狀態／AI／目標，統一 L03 投影 | 本機 React 18.3.1、Vite 4.5.5、TS 5.6.3；不加 runtime 依賴。DOM 圖層、遮擋、動畫管理需自己維護；尚無效能不足證據 | 60 分鐘有界機制 PoC：99 格、占點與離點、敵人干擾、進度／期限、重試，用圓點即可；以可維護的獨立Demo模組起步，接著才補完整循環。操作與命令格一致、無動畫可判定結果，才繼續 |
| B React＋Phaser | React 故事／HUD 與純 TS 規則可保留；SVG renderer、事件橋接、相機、格線命中、焦點需重建 | 已查模板 1.2.0 實際依賴 Phaser 4.0.0／React ^19／Vite ^6.3.1，不能整包覆蓋。本身不是「Phaser 必定要求 React 19」的證明；自寫 adapter 與現有工具鏈相容性仍未執行驗證。雙生命週期／canvas 可及性增加成本 | 日後另行授權、另枝 1.5–2.5h：先確認固定 Phaser 版本與 Vite4建置，再讓同一 MapDef＋事件 trace 驅動 99 格 canvas；只搬渲染、不重寫規則。20 次掛載卸載無殘留監聽，720/1080命中一致；若無已量測 SVG 痛點，延後 |
| C 未來 Godot | 可保留原創素材、地圖／目標 schema、驗收 trace；React UI、TS 執行碼無直接重用保證 | 參考專案各自 Godot 4.4 與 4.3，不能混用「Godot4」模糊帶過；場景、輸入、HUD、測試與資料載入都需重寫，另有桌面打包流程 | 日後另行授權、獨立目錄 3–5h：固定版本建立原創 11×9 blockout、兩單位、走格／攻擊／結束、相同 trace 校驗。記錄 TS→GDScript 搬移成本與桌面執行證據；本輪不裝 Godot、不決定正式引擎 |

Phaser 的 [Scenes](https://docs.phaser.io/phaser/concepts/scenes)、[Tilemap 4.0.0](https://docs.phaser.io/api-documentation/4.0.0/class/tilemaps-tilemap) 與 [Tweens](https://docs.phaser.io/phaser/concepts/tweens) 可管理場景、地圖資料／圖層與插值；目標、AI、勝敗仍由我們定義。這些是文件能力，尚非本專案相容性或效能實測。

B 場景仍供方向比對；第一個可玩版用同源格子與簡化地景，不把舊版美術滿意度當作玩法前置通過。正式美術整合另做座標校準、船／車隊分層、遮擋與可讀性驗收。
