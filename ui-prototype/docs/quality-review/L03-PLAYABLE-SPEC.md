# L03「可以輸」的最小戰鬥規格

**狀態　實作提案，未實作。** 這份規格交給負責戰鬥畫面的代理。所有數值都是**暫定**，只用來驗證「L03 能不能成為一場有策略判斷的戰鬥」，不得寫入 G005、不得當成正式規則，畫面上也要標示「暫定數值」。來源是《碑誓》[L03 設計稿](https://github.com/Gavin0099/campaign-forge/blob/story/strengthen-narrative/docs/story/levels/L03.md)與 ch01.ink 的 `L03_battle_open`／`L03_battle_sealed`。

## 先修的問題：開閘路線的目標根本到不了

現行 `l03Scene.ts` 的河道貫穿全部 9 列，唯一的通道是第 5 列的橋。開閘時橋面 (4,4)、(5,4) 不能通行，我方三人都在西岸，絞盤 (8,1) 卻在東岸。用 BFS 從凱倫出發計算，開閘時東岸 45 格**一格都到不了**；封閘時全部可達。

也就是說，在現在的地圖上，「守住絞盤」是做不到的目標。art-gate 場景也把「01 絞盤高台」畫在東岸，問題相同。

**修正：** 絞盤移到西岸 (2,1)。這也符合劇本：議會騎士在我方這一側轉動絞盤。東岸只留給封閘路線的車隊。

## 設計目標

1. 消極不動一定會輸。
2. 兩條路線要用**不同的打法**才能贏：開閘是守點，封閘是護送。
3. 敵人的下一步可以預測，輸的時候玩家知道自己錯在哪。
4. 只重用現有素材：騎士、爬行者、三名隊員的圖，不需要新美術。

## 共用規則

| 項目 | 規則 |
| --- | --- |
| 回合順序 | 我方階段 → 敵方階段 → 事件階段（增援、船隻、車隊移動）→ 下一回合 |
| 移動 | 沿用 `movementCells` 的 BFS，3 步；可以穿過友軍，不能停在有人的格子；不能穿過敵人 |
| 傷害 | 固定值，不擲骰。第一版刻意不加命中率，讓勝負只取決於判斷 |
| 敵方意圖 | 敵方階段開始前，每個敵人頭上顯示箭頭與目標（「→ 絞盤」「→ 車隊」「→ 蕾絲」）。這是讓玩家能做判斷的關鍵，不能省略 |
| 增援預告 | 增援的出生格提前一回合亮起 |
| 撤銷 | 保留現有「撤銷未確認操作」；不加整回合回溯 |
| 共同敗北 | 凱倫生命歸零 |

| 角色 | 生命 | 範圍 | 效果 | 起始格 |
| --- | --- | --- | --- | --- |
| 凱倫（戰士） | 9 | 1 | 傷害 3 | (2,5) |
| 蕾絲（盜賊） | 7 | 2 | 傷害 2 | (1,3) |

## 開閘：守住絞盤

| 項目 | 規則 |
| --- | --- |
| 勝利 | 撐過 5 回合；第 2、4、5 回合各有一艘船靠岸（第三艘是提歐的船） |
| 敗北 | 閘門進度累積到 3，或凱倫倒下 |
| 閘門進度 | 敵方階段**開始時**已經站在絞盤旁邊的騎士，每名 +1。換句話說，騎士必須在絞盤旁撐過一整個我方階段才能轉動，玩家永遠有一次反應機會 |
| 議會騎士 | 生命 5、移動 3、範圍 1、傷害 3，共 5 名 |
| 騎士行動 | 走最短路線前往絞盤旁的空格；移動後若身旁有我方，攻擊生命最低者 |
| 出現時機 | 開場：(1,8)、(3,8)；第 2 回合：(0,8)；第 3 回合：**(3,0)，從北側出現**；第 4 回合：(2,8) |
| 戰中事件 | 第 3 回合騎士隊長台詞（ch01.ink 已有） |

**要玩家做的判斷：** 西岸只有 4 格寬，騎士從南邊湧上來，是天然的守線。第 3 回合北側的增援會繞到隊伍背後。玩家必須決定什麼時候分一個人回頭守，不能全員往南推。

## 封閘：護送車隊過橋

| 項目 | 規則 |
| --- | --- |
| 勝利 | 學院車隊抵達西端出口 (0,4) |
| 敗北 | 車隊生命歸零、第 7 回合結束仍未抵達，或凱倫倒下 |
| 車隊 | 生命 12，從 (8,4) 出發，每個事件階段沿第 5 列往西走 2 格；**下一格有任何單位就停住，包括我方** |
| 裂潮爬行者 | 生命 4、移動 2、範圍 1、傷害 2，共 6 隻 |
| 爬行者行動 | 走向車隊；身旁有車隊就攻擊車隊，否則攻擊身旁的我方 |
| 出現時機 | 開場：(6,1)、(6,7)；第 2 回合：(3,2)；第 3 回合：(6,6)；第 4 回合：(3,6)；第 5 回合：(6,2)。全部從河岸登陸 |
| 落水者（次要，不影響勝敗） | 河岸 3 個標記格。我方在回合結束時站在上面就救起一人，結算時顯示人數 |
| 戰中事件 | 第 2 回合「提歐的燈滅了」；第 4 回合蕾絲台詞（ch01.ink 已有） |

**要玩家做的判斷：** 隊伍必須過橋迎向車隊，但橋只有一格寬，站錯位置會擋住車隊。殺光爬行者來不及；要清出車隊的路，又不能自己變成路障。救落水者會拖慢護送，這就是劇本「沿岸可救人」的取捨。

## 模擬器驗證

[l03-sim.py](l03-sim.py) 是獨立的紙上原型，用上表數值跑三種固定打法。它不是遊戲程式，敵方 AI 與上表規則一致，我方打法是寫死的簡單策略，不代表人類會怎麼玩。

```bash
python -I l03-sim.py
```

| 路線 | 消極（每回合直接結束） | 追殺（衝向最近的敵人） | 顧目標（守點或清路） |
| --- | --- | --- | --- |
| 開閘 | 第 4 回合輸，閘門落下 | 勝，閘門進度 2/3 | 勝，閘門進度 2/3，蕾絲剩 1 |
| 封閘 | 第 6 回合輸，車隊被毀 | 第 7 回合輸，時限到 | 第 4 回合勝，車隊剩 10/12 |

解讀：

- 兩條路線消極不動都會輸，達成目標 1。
- 封閘只有顧目標的打法能贏，追殺會超時。開閘時追殺也能贏，因為騎士會主動走進我方的攻擊範圍；兩條路線的最佳打法因此不同，達成目標 2。
- 開閘兩種贏法都只差一格閘門進度，代表一個失誤就會輸。作為第三關可能偏難，第一次人類試玩後應優先調整這裡；建議先調閘門門檻（3→4），不要先改騎士數量，因為騎士數量是劇本寫定的 5 名。
- 封閘的顧目標打法車隊只掉 2 點，可能偏易。可以把爬行者傷害提高到 3，或把第 5 回合的增援提前一回合。

這張表只能證明「規則有可能產生策略」，不能證明好玩。好不好玩只有人類試玩能回答，見 [PLAYTEST-PROTOCOL](PLAYTEST-PROTOCOL.md)。

## 驗收方式（給實作者）

1. `quality-review-audit.mjs` 的 B3 改寫成 L03 版本：比對開閘與封閘開場的敵人組成和勝利條件，兩者必須不同。
2. 新增瀏覽器檢查：
   - 連按 5 次「結束回合」，開閘必定輸。
   - 封閘時把凱倫停在 (6,4)，車隊必定停住。
   - 第 3 回合開始時，北側增援格必須已經預告。
3. 用模擬器表中「顧目標」的固定走法在瀏覽器重放一次，結果要和模擬器一致。如果不一致，代表實作和規格有落差，要先查清楚，不要直接調數值讓結果吻合。
4. 畫面上所有數值旁標示「暫定」，戰後結算不得寫入任何正式旗標或存檔。

## 不在本規格範圍

命中率、反擊、地形加成、經驗值、裝備、敵方頭目、水位每回合上升、提歐之船的單獨護送。這些都等 G005 規則基礎決定後再談。
