# 真人試玩流程（3 人版）

**狀態　流程範本，尚未執行，回饋紀錄為空。** 目的是回答代理無法回答的問題：這場戰鬥和這個故事，陌生玩家會不會在乎。本流程不需要任何網路服務，不錄影、不收集可識別個人的資料。

## 什麼時候做

| 輪次 | 試玩對象 | 前提 |
| --- | --- | --- |
| A 輪 | 《碑誓》L01–L07 文字試讀（分支既有的 `story-playtest`） | 現在就可以做，不需要新程式 |
| B 輪 | L03 可輸版本（[L03 規格](L03-PLAYABLE-SPEC.md)實作後） | 需要負責戰鬥的代理先完成實作 |

兩輪可以找同一批人，但 **B 輪必須是他們第一次玩 L03**；先讀過 A 輪的人，對 K1 已經有預期，要在紀錄中註明。

## 招募

- 3 人，沒看過本專案的任何文件或畫面。
- 至少 1 人平常玩戰棋（火焰紋章、Into the Breach、Tactics Ogre 這類），至少 1 人很少玩。
- 不需要姓名，紀錄只用 T1、T2、T3。不記錄年齡、性別、聯絡方式。

## 主持人的規則

1. 只說：「這是一個還在做的戰棋遊戲原型，請邊玩邊把想到的說出來。我不會幫你，卡住就說卡住。」
2. **不解釋任何規則或故事。** 玩家問「這是什麼」，回答「你覺得是什麼？」並記下問題本身。這些問題就是資料。
3. 不要說「這裡設計上應該……」。玩家誤會的地方就是要找的問題。
4. 每人 30 分鐘以內，超時就停。

## A 輪：文字試讀（約 20 分鐘）

分支的 [L01–L07 試讀說明](https://github.com/Gavin0099/campaign-forge/blob/story/strengthen-narrative/docs/story/playtest/L01-L07.md)已經列好回饋題目，直接使用，不要自己改寫。主持人額外記錄：

| 觀察點 | 記什麼 |
| --- | --- |
| 第一場戰鬥前 | 玩家問了哪些名詞是什麼（對應 [L01–L07 審查](L01-L07-REVIEW.md) 的 QR-13） |
| K1 | 選了哪邊、花多久、選之前說了什麼。**不要事先問「你覺得哪邊比較好」** |
| L07 | 讀到三選一時，是否抗議「我剛剛不是保護他們了嗎」（QR-10） |

## B 輪：L03 可輸版本（約 25 分鐘）

1. 不給任何說明，讓玩家從戰前情報開始。
2. 第一場由玩家自選開閘或封閘，打完後（不論輸贏）再打另一邊。
3. 主持人在每回合記錄：

| 欄位 | 範例 |
| --- | --- |
| 回合 | 3 |
| 玩家說的話（盡量逐字） | 「後面怎麼又來一個」 |
| 玩家是否看了敵方意圖箭頭 | 是／否／不確定 |
| 這回合的關鍵決定 | 把托瑪留在北邊 |

4. 打完每一場後問三題，先讓他們自由說，再追問：
   - 「你這場的目標是什麼？」能否說出「守住絞盤」或「讓車隊過橋」，而不是「打倒敵人」？
   - 「輸（或差點輸）是因為什麼？」答案指向自己的判斷，還是指向「規則看不懂」或「運氣」？
   - 「兩條路線打起來一樣嗎？」

5. 最後一題：「如果還有下一關，你想玩嗎？為什麼？」

## 怎麼判讀

不打分數、不算平均。3 個人樣本太小，只看**是否出現某種現象**：

| 現象 | 代表什麼 | 下一步 |
| --- | --- | --- |
| 有人說不出目標 | Q1 沒有解決 | 先改目標的畫面呈現，不要先調數值 |
| 有人把輸歸咎於「看不懂敵人要做什麼」 | 意圖預告不夠清楚 | 改意圖箭頭 |
| 3 人都覺得兩條路線打起來一樣 | Q2 沒有解決 | 回頭檢查規格實作 |
| 平常玩戰棋的人也在開閘輸了 2 次以上 | 開閘太難 | 依規格建議，把閘門門檻 3→4 |
| 3 人都選開閘，理由是「比較多人」「比較好打」 | QR-11 成立 | 把封閘的戰鬥收益提案交給 Gavin |
| 有人主動說想玩下一關，而且說得出想追哪個人物 | 第一個正面訊號 | 可以開始評估下一個可玩關卡 |

## 紀錄格式

每人一份 Markdown，放在 `docs/quality-review/playtest/T1.md` 等位置。開頭註明：

- 試玩日期、版本 commit、輪次（A／B）
- 是否先讀過其他輪
- 主持人是誰

**不要把代理的推測寫進紀錄**，也不要事後替玩家「整理」措辭。代理可以協助彙整，但彙整必須標明是彙整，原始紀錄要保留。

## 這份流程不處理的事

- 數值平衡。3 人無法回答，只能找出明顯過難或過易的地方。
- 美術品質。需要另外的 Owner 審查。
- 商業可行性。
